01 · Hardware it runs on

Cardputer-Adv × Cap LoRa868

The Cap clips onto the Adv's 14-pin EXT header (Cap-Bus). It carries an SX1262 LoRa radio on SPI and an ATGM336H GPS on UART — so location and accurate UTC time are available to every app for free.

SPIThe radio shares its SPI bus with the microSD slot (SCK G40 / MOSI G14 / MISO G39, separate chip-selects). Any app that logs to card — Breadcrumb, Monitor capture — must arbitrate bus access with the radio: guard transfers behind a single bus mutex and never hold both CS lines low at once.

GPSGPS delivers position and disciplined UTC — the Adv has no RTC, so message timestamps, log filenames and the duty-cycle window all key off GPS time once a fix is acquired (falling back to millis() uptime before fix).

RXReception is interrupt-driven off DIO1: the ISR just flags a ready packet, the main loop drains it, verifies CRC + channel, updates the node table, then hands it to the foreground app and the background Relay. So mesh forwarding keeps working no matter which app is open.

05 · The rule everything obeys

Duty-cycle governor

868 MHz is a shared, regulated band — most EU sub-bands cap transmit airtime at 1% (some 0.1%). A single governor in LoRaService meters every transmission's time-on-air against a rolling window and throttles or queues the app when the budget runs low. Beacon intervals, mesh rebroadcast and file transfer all defer to it.

Rolling airtime — last 3600 s window612 ms / 36 000 ms budget
1.7% used · sending clear SF9 · BW125 · 40-byte frame ≈ 144 ms on air

06 · Shipping it

Project layout & build order

One PlatformIO project (Arduino framework, ESP32-S3). The protocol, airtime and crypto code is pure C++ with native unit tests — testable on the host with no hardware, per the always-test rule.
